# M2：工单数据库与仓储层

> 预计 6-10 小时。目标：用标准库 `sqlite3` 建一个可重复初始化的工单库，写出清晰的仓储层，并用 CLI 完成列表、详情、创建和状态更新。

## 先理解：这一层为什么重要

后面的 Agent 要调用 `get_customer`、`get_order`、`get_ticket`、`create_ticket`、`update_ticket`、`escalate_to_human` 这些工具。工具本身不直接写 SQL，而是调用**仓储层**。

```text
CLI / FastAPI / Agent 工具
        ↓
repositories.py        # 业务数据访问：参数校验、SQL、事务
        ↓
connection.py          # 连接、row_factory、PRAGMA
        ↓
data/app.db            # SQLite 文件
```

这一层做好，后面 Agent 的写操作、幂等和审计才有地方落。

M2 只做数据库和 CLI，不接 FastAPI，不接 LLM，不写 Agent。

### 2. 连接层

`app/db/connection.py` 至少提供：

```python
def get_connection(db_path) -> sqlite3.Connection:
    ...

def init_db(db_path) -> None:
    ...
```

**要求**

- `get_connection()`：
  - 创建连接；
  - 设置 `conn.row_factory = sqlite3.Row`；
  - 执行 `PRAGMA foreign_keys = ON`；
  - 执行 `PRAGMA journal_mode = WAL`；
  - 返回连接。
- `init_db()`：
  - 读取 `schema.sql`，用 `executescript()` 建表；
  - 可重复执行，不报错。
- 明确连接什么时候关闭。CLI 里可以用 `try/finally`，也可以自己封装上下文管理器。

**提示**

- `sqlite3.connect()` 默认不会自动打开外键约束，必须每个连接执行 `PRAGMA foreign_keys = ON`。
- `executescript()` 适合执行多条建表语句。
- `with conn:` 管的是**事务**，不是关闭连接。

### 3. 仓储层

`app/db/repositories.py` 至少实现下面这些函数。函数都接收 `conn`，不要在函数内部重新创建连接。

```python
def get_customer(conn, customer_id: str) -> dict | None:
    ...

def get_order(conn, order_id: str) -> dict | None:
    ...

def list_tickets(
    conn,
    status: str | None = None,
    customer_id: str | None = None,
) -> list[dict]:
    ...

def get_ticket(conn, ticket_id: str) -> dict | None:
    ...

def list_ticket_events(conn, ticket_id: str) -> list[dict]:
    ...

def create_ticket(
    conn,
    customer_id: str,
    title: str,
    description: str,
    order_id: str | None = None,
    priority: str = "normal",
    actor: str = "cli",
) -> dict:
    ...

def update_ticket_status(
    conn,
    ticket_id: str,
    new_status: str,
    actor: str,
    note: str,
) -> dict:
    ...
```

**要求**

- 所有 SQL 都用 `?` 占位符，禁止 f-string 拼接用户输入。
- `list_tickets()` 支持按状态和客户过滤；没有过滤条件时返回全部。
- `create_ticket()`：
  - 生成工单 ID，例如 `TKT-` + 8 位大写十六进制；
  - 校验客户存在，不存在时抛出明确异常；
  - 如果传了 `order_id`，校验订单存在，并且订单属于该客户；
  - 插入工单；
  - 同时插入一条 `created` 事件；
  - 两步必须在同一个事务里。
- `update_ticket_status()`：
  - 校验工单存在；
  - 更新 `status` 和 `updated_at`；
  - 插入一条 `status_changed` 事件；
  - 两步必须在同一个事务里；
  - 返回更新后的工单。
- 查询结果统一转成 `dict`，不要把 `sqlite3.Row` 直接丢给 CLI 或未来的 API。
- 业务错误用自定义异常，例如 `NotFoundError`、`ValidationError`，不要让 CLI 去猜 `None` 的含义。

**事务提示**

```python
try:
    with conn:
        conn.execute(...)
        conn.execute(...)
except Exception:
    # with conn: 已经回滚
    raise
```

`with conn:` 在正常结束时提交，异常时回滚；它不会自动关闭连接。

def seed_data(conn) -> None:
    ...

**要求**

- 插入 3 个客户，ID 固定，例如 `C001/C002/C003`。
- 插入 3 个订单，ID 固定，例如 `O001/O002/O003`。
- 插入 3 个工单，ID 固定，例如 `TKT-1001/TKT-1002/TKT-1003`，状态覆盖 `open`、`in_progress`、`resolved`。
- 每个工单至少插入 1 条事件。
- **可重复执行**：第二次运行不能重复插入，也不能报主键冲突。

**提示**

- 固定 ID 是幂等的基础。
- 可以用 `INSERT OR IGNORE`，也可以先查再插；要能解释两者的区别。
- 不要用随机数生成种子 ID，否则第二次运行会插出重复数据。

### 5. CLI

`scripts/ticket_cli.py` 用 `argparse` 子命令实现：

```text
python -m scripts.ticket_cli init-db
python -m scripts.ticket_cli seed
python -m scripts.ticket_cli list
python -m scripts.ticket_cli list --status open
python -m scripts.ticket_cli list --customer C001
python -m scripts.ticket_cli show TKT-1001
python -m scripts.ticket_cli create --customer C001 --order O001 --title "退款申请" --description "商品破损，申请退款" --priority high
python -m scripts.ticket_cli update TKT-1001 --status resolved --actor agent --note "已电话联系客户"
```

**要求**

- `init-db`：建表，不插入种子数据。
- `seed`：建表后插入种子数据；重复执行不重复插入。
- `list`：表格或对齐文本输出，至少显示 ID、客户、标题、状态、优先级、更新时间。
- `show`：显示工单详情和事件时间线。
- `create`：创建成功后打印新工单 ID；客户不存在、订单不属于客户时给出明确错误并返回非零退出码。
- `update`：更新状态并写事件；非法状态给出明确错误并返回非零退出码。
- 所有错误信息走 `stderr`，正常数据走 `stdout`。
- 不要在 CLI 里直接写 SQL；CLI 只调用仓储层。

**提示**

- `argparse` 的 `add_subparsers(dest="command")` 可以组织子命令。
- 连接用 `try/finally` 关闭。
- 退出码：成功 `0`，参数或业务错误 `1`，未预期异常可以让 Python 自然抛出 traceback，但验收时不应出现。

## 提示

- 先写 `schema.sql`，用 `sqlite3` 命令行或 `init-db` 建表，再写仓储层。
- 不要一上来写 CLI；先让 `create_ticket()` 在 Python 交互里跑通。
- 每次写完一个仓储函数，就用一个小脚本或交互式解释器验证返回值。
- 时间统一用 UTC ISO 8601 字符串，例如 `2026-10-27T03:20:00+00:00`。
- `sqlite3.Row` 支持 `row["字段名"]`，但转成 `dict(row)` 后更好传给上层。
- 如果外键插入没有报错，先检查是否执行了 `PRAGMA foreign_keys = ON`。
- 如果 `seed` 第二次报主键冲突，说明幂等没做好。
- 如果 `create_ticket()` 只写入了工单、没有事件，检查两条 `execute` 是否在同一个 `with conn:` 里。
- 不要用 ORM；M2 的目的就是手写 SQL 和事务。
