# M6：FastAPI 服务

> 预计 8-12 小时。目标：把 M2 的工单仓储和 M4/M5 的 RAG 链路暴露成 HTTP 接口，用 Pydantic 做入参校验、用状态码表达结果、用 OpenAPI 自动生成文档。

## 先理解：为什么要有这一层

到 M5 为止，所有能力都只能通过 `python -m scripts.xxx` 使用。这意味着：

| 问题 | 后果 |
|---|---|
| 只有你能用 | 别人要装环境、记命令 |
| 没有契约 | 参数改了没人知道，出错了只能看报错栈 |
| 不能并发 | 一次一个终端，跑完就结束 |
| 不能接界面 | M8 的 Streamlit 无从对接 |

HTTP 层的价值不是"更高级"，是**把能力变成契约**：路径、方法、入参、出参、错误码都写死，调用方不需要读你的 Python 代码。

```text
M5 之前： 你 → 命令行 → Python 函数
M6 之后： 任何客户端 → HTTP → 同一批 Python 函数
```

**这一层不产生新能力，只做翻译。** 如果发现要在 API 里重写检索或工单逻辑，说明抽错了位置。

## 概念速览

### HTTP 方法与状态码

| 方法 | 语义 | 本项目用途 | 成功码 |
|---|---|---|---|
| GET | 读取，无副作用 | 查工单、健康检查 | 200 |
| POST | 创建 / 执行动作 | 建工单、提问 | 201 / 200 |
| PATCH | 局部更新 | 改工单状态 | 200 |
| DELETE | 删除 | 本项目不用（工单只关不删） | — |

| 状态码 | 含义 | 本项目触发点 |
|---|---|---|
| 200 | 成功 | 查询、提问 |
| 201 | 已创建 | 建工单 |
| 400 | 请求本身有错 | 业务规则不满足（如空标题） |
| 404 | 资源不存在 | 工单 id 不存在 |
| 422 | 结构校验失败 | Pydantic 自动返回，字段缺失/类型错 |
| 502 | 上游失败 | LLM 调用失败 |
| 503 | 本服务暂不可用 | 向量库为空 |

**422 和 400 的区别**：422 是"请求格式不合法"（FastAPI 自动给），400 是"格式合法但业务上不允许"（你手动抛）。

### FastAPI 的三件套

```python
app = FastAPI()                      # 应用
@app.get("/health")                  # 路由装饰器：方法 + 路径
def health() -> dict:                # 处理函数
    return {"status": "ok"}
```

### Pydantic 模型

```python
class AskRequest(BaseModel):
    question: str = Field(min_length=1, max_length=500)
    top_k: int = Field(default=4, ge=1, le=20)
    mode: Literal["vector", "bm25", "hybrid"] = "hybrid"
```

`Field` 的约束会在进入你的函数**之前**生效，不合法直接 422。这就是"契约"的具体形态：校验写在模型里，不用在每个函数里 `if not ...`。

### 同步还是异步

现有代码里，`search_hybrid` 是 CPU 密集（jieba + BM25 + 向量打分），`chat()` 是 `httpx` 的**同步**调用，`sqlite3` 也是同步的。所以：

- 路由写成 **`def`** → FastAPI 把它丢到线程池执行，不阻塞事件循环；
- 写成 `async def` 却在里面调同步阻塞函数 → **阻塞整个事件循环**，并发直接退化成串行。

```text
def 路由        → 线程池，多个请求可以并行
async def 路由  → 事件循环；内部同步调用会把循环卡住
```

M8 之后如果换成 `httpx.AsyncClient`，那时才考虑 `async def`。**现在全部用 `def`。**

### 2. 数据库连接依赖

**要求**

- 用 `Depends` + `yield` 提供连接，请求结束自动关闭：

```python
def get_db():
    conn = get_connection(settings.db_path)
    try:
        yield conn
    finally:
        conn.close()
```

### 3. 问答接口 `POST /ask`

**要求**

- 入参：`question`、`top_k`（默认 4）、`mode`（默认 `hybrid`）。
- 出参：`answer`（字符串）、`citations`（`[{"n":1,"doc":"退款政策","section":"5. 退款时效与路径"}]`）、`hits`（检索命中的 `doc_id`/`section`/`score`）。
- 行为必须和 CLI 一致：**没有检索到资料时直接返回固定话术，不调用模型**。
- 向量库为空 → 503；LLM 失败 → 502。**不要**让异常直接变成 500 和一堆堆栈。

#### 3.1 这条要求没有规定、但你必须自己决定的事

上面的"要求"是**验收标准**，不是施工图。它只说了"结果必须是什么样"，没说"代码长什么样"。下面这些自由度它一句没提，实现时必须由你做决定，并且能说出理由——这才是这部分的真正难点：

| 待决定 | 可选做法 | 为什么有唯一正确答案 |
|---|---|---|
| 代码放哪 | 全塞 `main.py` / 模型单独 `schemas.py` | 模型会被任务 4、5 复用，单独放 |
| `question` 的空值边界 | 只写 `min_length=1` / 加 `strip()` 校验 | `"   "` 长度是 3，能骗过 `min_length` |
| `hits` 要不要返回片段全文 | 要 / 不要 | 默认不要，响应体从 1KB 涨到几十 KB |
| `citations` 的 `n` 从哪来 | 自己编号 / 复用 hits 下标 | 必须能和 `hits` 对上，否则调用方无法点击溯源 |
| 模型输出 `[5]` 越界怎么办 | 透传 / 丢弃 | 越界就是伪造引用，丢弃 |
| 同一引用出现两次 | 两条 / 一条去重 | 去重 |
| 错误响应该写什么 | `str(exc)` / 固定话术 | 固定话术，`exc` 可能带 URL 和响应体片段 |
| 路由 `def` 还是 `async def` | 都行 / 必须 `def` | 见"注意"节：同步调用不能进 async |
| 要不要注入 `get_db` | 统一注入 / 按需注入 | `/ask` 不碰数据库，不要 |

**如果你觉得"任务书里读不出这个做法"——是对的。** 任务书读不出实现，是因为它故意只写结果。读任务书的正确方式不是"照着翻译成代码"，而是对每一条要求追问三个问题：

1. **输入是什么形状？** → 决定数据模型有哪些字段、什么类型、什么默认值。
2. **这个错误最早能在哪一步拦住？** → 决定校验写在 `Field` / `field_validator` / 路由内 / `exception_handler`（越早越便宜）。
3. **失败时调用方看到什么？** → 决定状态码和 `detail` 文案。

#### 3.2 两个例子：要求 → 结论 → 代码

**例 1：`min_length=1` 这条要求推不出"加 validator"**

```text
要求：question 不能为空
最小实现：question: str = Field(min_length=1)     ← 看起来满足了
反例：    {"question": "   "}  → 长度 3，通过校验，模型收到空问题
结论：    需要先 strip() 再判空 → field_validator
```
推导链不是从要求直接到代码，而是**要求 → 举反例 → 补上反例覆盖不到的洞**。你写每个校验时都该问一句"什么样的输入能骗过它"。

**例 2：`hits` 的要求里没写 `n`，但 `n` 是推出来的**

```text
要求 A：citations 形如 {"n": 1, "doc": "...", "section": "..."}
要求 B：hits 列出命中的 doc_id / section / score
矛盾：  citations 说"第 1 条"，调用方要拿什么去 hits 里找第 1 条？
结论：  hits 必须能按序号定位 —— 要么显式加 n，要么约定"列表位置即 n"
```
这就是"两个要求放在一起才产生的第三个要求"。设计时不要一条一条孤立地看。

#### 3.3 施工顺序（每一步都能单独验证，别一次写完）

| 步 | 写什么 | 不写什么 | 怎么验证 |
|---|---|---|---|
| 1 | `schemas.py` + 空路由 `return AskResponse(answer="", citations=[], hits=[])` | 不碰检索、不碰模型 | `/docs` 能看到请求体示例；空 `question` 返回 422 |
| 2 | 路由里加 `search_hybrid`，把 `hits` 填进响应 | 还不调模型 | 返回的 `hits[0].n == 1`，条数等于 `top_k` |
| 3 | 加 `if not hits:` 拒答分支 | 还不调模型 | 库外问题返回固定话术，响应几乎瞬时 |
| 4 | 加 `build_messages` + `chat` + `_extract_citations` | 还没接错误码 | 库内问题的 `citations[].n` 在 `answer` 里能找到 `[n]` |
| 5 | 加 `except IndexEmptyError` / `except LLMError` | — | 两个状态码各自触发一次 |

**为什么按这个顺序**：前 3 步完全不花钱、不依赖网络，出错时排查面只有一处。第 4 步才引入外部依赖。如果你一上来把 5 步一起写完再调试，任何一个 500 你都得同时怀疑检索、模型、引用解析三处。

### 4. 工单读接口

```text
GET /tickets?status=open&customer_id=C001
GET /tickets/{ticket_id}
```

**要求**

- 列表支持可选过滤，参数不传就不过滤。
- 详情返回工单本身 + `events` 列表（`list_ticket_events`）。
- id 不存在 → 404，响应体里有可读的 `detail`。

#### 4.1 必须自己决定的事

| 决定 | 推荐 | 理由 |
|---|---|---|
| 列表形状 | 裸数组 | 无分页需求；把"没分页"记为已知限制 |
| `status` 过滤类型 | `Literal[...] \| None` | 用 `str` 时拼错 `opne` 静默返回 `[]`，和"真的没工单"无法区分 |
| 详情形状 | 平铺 + `class TicketDetail(TicketOut)` | 调用方少一层解包 |
| `get_ticket` 返回 `None` | 显式 `HTTPException(404)` | 放任 None 会让 `response_model` 校验失败 → **500**，不是 `null` |
| 路由里手拼字段 | 不拼，直接 `return` dict | `response_model` 运行时过滤字段 |

#### 4.2 施工顺序

| 步 | 写什么 | 怎么验证 |
|---|---|---|
| 1 | 三个模型 + 全量列表 | `/docs` 有模型；条数对 |
| 2 | 加两个查询参数 | `?status=opne` → 422 |
| 3 | 详情，**先不加 None 判断** | 不存在的 id → 亲眼看到 500 |
| 4 | 加 404 和 events | 不存在 → 404；存在 → 有 events |

第 3 步是故意的：亲手制造一次 500，比记住"要判 None"管用。

### 5. 工单写接口

```text
POST  /tickets              → 201，返回新工单
PATCH /tickets/{id}/status  → 200，返回更新后的工单
```

**要求**

- 入参用 Pydantic 模型，`priority` / `status` 用 `Literal` 限定取值（宁可让 FastAPI 返 422，也不要自己写 if-else）。
- `actor` 不要由客户端随便填，服务端固定为 `"api"`（审计字段不能被调用方伪造）。
- `update_ticket_status` 抛的 `ValidationError`（比如状态流转不合法）→ 400 或 409，你自己选一个并写进文档。

#### 5.1 必须自己决定的事

| 决定 | 推荐 | 理由 |
|---|---|---|
| `actor` 放进模型 | 绝不 | 否则客户端可以冒充人工客服 |
| 201 的 `Location` 头 | 路由签名加 `response: Response` | 比返 `JSONResponse` 简单，保留 `response_model` 过滤 |
| `priority` 默认值 | 模型里 `="normal"` | 不在路由里写 `or "normal"` |
| `note` 是否必填 | 默认 `""`，服务端生成默认文案 | 状态变更必须留事件，但不该强制客户端写说明 |
| 非法流转的状态码 | **409** | 400 是"请求错"，409 是"与资源当前状态冲突" |
| 同状态设两次 | 允许并记事件 | 减少分支；文档写明 |

**错误码分配**：工单/客户不存在 → 404；订单不属于该客户 → 400；非法流转 → 409；`status` 不在枚举 → 422。

#### 5.2 ⚠️ 开工前先补的缺口

`update_ticket_status` 现在**只校验状态值合法，没有流转规则**，`closed → open` 会成功；而 `Literal` 已在入口挡掉非法值，所以那句话实际触发不到。必须加 `_ALLOWED` 流转表，**放 repository 不放 API**——否则 `ticket_cli.py` 能绕过规则。

#### 5.3 施工顺序

| 步 | 写什么 | 怎么验证 |
|---|---|---|
| 1 | `TicketCreate` + `POST /tickets`，actor 写死 | 201、`Location` 头、响应体是新工单 |
| 2 | 接 `NotFoundError` / `ValidationError` | 客户不存在 → 404；`order_id=O002` 配 `C001` → 400 |
| 3 | `StatusUpdate` + `PATCH /tickets/{id}/status` | 200，返回更新后的工单 |
| 4 | repository 加流转表 | `closed → open` → 409 |
| 5 | `GET /tickets/{id}` 回看 | `events` 里有 `status_changed` |

第 5 步是关键：**写接口的正确性用读接口证明**，只看 PATCH 的 200 不能说明事件真写进去了。

测试数据：客户 `C001/C002/C003`，订单 `O001→C001`、`O002→C002`，工单 `TKT-1001`（open）。

## 提示与坑

- **别在 API 里重写检索逻辑。** 直接调 `search_hybrid`、`build_messages`、`chat`。如果发现 CLI 的编排逻辑（拒答分支、引用解析）需要复用，就把它抽成函数，而不是复制一遍。
- **`response_model` 会过滤字段。** 数据库行里有 `created_at` 之类不想暴露的字段，靠它挡；同时它也是 OpenAPI 文档的数据来源。
- **Pydantic v2**：`model_dump()` 代替 v1 的 `dict()`；`Field(ge=1)` 这类约束直接用，不要手写校验。
- **`Literal` 比枚举更省事**：`Literal["open","in_progress",...]` 会出现在 `/docs` 的下拉里，非法值自动 422。
- **`conn.row_factory = sqlite3.Row` 才能 `dict(row)`**，连接层已经处理好，别另建连接。
- **`/ask` 会慢**（embedding + 给模型）。先不管性能，M9 再谈缓存。
- **别把 `traceback` 直接返回给客户端**：信息泄露，而且对调用方没用。
- **uvicorn 的 `--reload` 会重载模块**，如果 BM25 缓存建得慢，改代码后第一次请求会明显变慢，属正常。
