# M3：调用大模型

> 预计 8-12 小时。目标：用 `httpx` 手写一个 OpenAI 兼容的 chat 客户端，通过 CLI 发一个问题并打印模型回答；API Key 只从环境变量读取，错误可读，退出码可验收。

## 先理解：为什么要手写 HTTP，而不是直接 `import openai`

模型服务对外的契约就是 HTTP：

```text
我们的代码
   │  POST {base_url}/chat/completions
   │  Authorization: Bearer <API_KEY>
   │  Content-Type: application/json
   ▼
模型服务（DeepSeek / OpenAI / 其他兼容服务）
   │  200 + JSON
   ▼
choices[0].message.content
```

`openai` SDK 只是把这层 HTTP 封装成了函数。先手写一遍，你才能解释：

- 请求失败时是网络问题、Key 问题、额度问题还是参数问题；
- 401、429、500 分别该不该重试；
- 超时到底卡在哪一段；
- 以后接流式输出（SSE）时，底层在传什么。

M3 只用 `httpx` 发请求、`json` 解析响应，不引入 `openai` SDK、不引入 LangChain。M4 做 RAG 时仍然复用这个客户端。

## 任务

### 1. 扩展配置

`app/config.py` 里已经有：

```python
self.llm_BASE_URL = os.getenv("LLM_BASE_URL", "https://api.deepseek.com/v1")
self.llm_MODEL = os.getenv("LLM_MODEL", "deepseek-chat")
self.llm_API_KEY = os.getenv("LLM_API_KEY", "")
self.mock_mode = not self.llm_API_KEY.strip()
```

要求：

- 新增两个可配置项，仍然只从环境变量读：
  - `llm_timeout`：秒，默认 30；
  - `llm_max_tokens`：输出上限，默认 512。
- 不要重命名现有的四个属性。`llm_BASE_URL` 这种大小写混用的命名是 M0 留下的债，M6 再统一，现在改会牵连 `check_env.py`。
- 不要在 `config.py` 里加载 `.env`，也不要引入 `python-dotenv`。M3 就用系统环境变量。

**Key 的设置方式（PowerShell）：**

```powershell
# 只对当前窗口有效
$env:LLM_API_KEY = "sk-你的key"

# 写入用户环境变量，需新开窗口才生效
setx LLM_API_KEY "sk-你的key"
```

为什么不在 CLI 上加 `--api-key` 参数：命令行参数会进 shell 历史、进程列表，容易被别人看到。Key 属于“凭据”，只应该走环境变量或密钥管理服务。

### 2. 客户端 `app/llm/client.py`

建议结构：

```text
app/
└─ llm/
   ├─ __init__.py
   └─ client.py
scripts/
└─ ask_llm.py
```

客户端对外至少提供：

```python
class LLMError(Exception):
    """LLM 调用相关错误的基类。"""

class LLMConfigError(LLMError):
    """配置缺失或不合法，例如没有 API Key。"""

class LLMRequestError(LLMError):
    """网络错误、超时、非 2xx 响应。"""

class LLMResponseError(LLMError):
    """响应能拿到，但结构不符合预期。"""

def chat(
    messages: list[dict[str, str]],
    *,
    temperature: float = 0.2,
    max_tokens: int | None = None,
) -> dict:
    """调用 chat/completions，返回 {"content": str, "model": str, "usage": dict | None}。"""
```

**请求要求：**

- URL：`base_url.rstrip("/") + "/chat/completions"`。默认值是 `https://api.deepseek.com/v1`，所以最终是 `.../v1/chat/completions`。
- Header：
  - `Authorization: Bearer <api_key>`
  - `Content-Type: application/json`
- Body：

```json
{
  "model": "<settings.llm_MODEL>",
  "messages": [
    {"role": "system", "content": "你是一个简洁、准确的中文客服助手。"},
    {"role": "user", "content": "你好"}
  ],
  "temperature": 0.2,
  "max_tokens": 512,
  "stream": false
}
```

- 超时：至少要区分连接超时和读超时，例如 `httpx.Timeout(30.0, connect=10.0)`。超时值来自 `settings.llm_timeout`。
- `max_tokens` 为 `None` 时使用 `settings.llm_max_tokens`。
-+
**响应要求：**

- 2xx 时解析 JSON，取 `choices[0]["message"]["content"]`。
- 同时返回 `model` 和 `usage`（`prompt_tokens` / `completion_tokens` / `total_tokens`），后面 M9 做观测时要用。
- `choices` 为空、`content` 为空、JSON 解析失败，都抛 `LLMResponseError`，不要返回空字符串让人猜。
- 非 2xx 时抛 `LLMRequestError`，异常信息里要包含**状态码和响应体摘要**，但**绝不能包含请求 header 或 API Key**。
- 连接失败、超时分别给出能看懂的中文信息。

**错误映射（建议）：**

| 状态码 | 含义 | M3 的处理 |
|---|---|---|
| 400 | 请求体不合法 | 打印服务端 `error.message`，修参数，不重试 |
| 401 | Key 缺失或无效 | 提示检查 `LLM_API_KEY`，不重试 |
| 403 | 无权限或额度不足 | 提示账号/额度问题，不重试 |
| 404 | URL 写错 | 打印最终请求 URL（不含 Key），检查 `base_url` |
| 429 | 限流 | 提示稍后重试；可选做一次退避重试 |
| 5xx | 服务端故障 | 可做有限次重试（最多 2 次，指数退避） |

**不要**对 400/401/403/404 自动重试——重试改变不了结果，只会浪费时间。

### 3. CLI `scripts/ask_llm.py`

用法：

```text
python -m scripts.ask_llm "你好"
python -m scripts.ask_llm "解释一下什么是 RAG" --system "你是一个耐心的老师"
python -m scripts.ask_llm "你好" --temperature 0.7 --max-tokens 200
python -m scripts.ask_llm "你好" --mock
python -m scripts.ask_llm "你好" --show-usage
```

要求：

- 第一个位置参数是用户问题，必填；空字符串视为参数错误。
- `--system` 可选，默认给一句中文客服助手的 system prompt。
- `--temperature` 默认 `0.2`，限制在 `0.0 ~ 2.0`。
- `--max-tokens` 默认取 `settings.llm_max_tokens`。
- `--mock`：不联网，直接打印一条固定回答，用于验证 CLI 管线。**没有 Key 且没加 `--mock` 时必须报错退出，不能静默改用 mock。**
- `--show-usage`：把 token 用量打印到 `stderr`，正常回答仍然只走 `stdout`。
- 退出码：成功 `0`；配置/网络/业务错误 `1`；argparse 参数错误 `2`。
- 预期错误不要打印 traceback；`except LLMError` 统一翻译成中文提示。

**为什么 mock 要显式开关：** 静默 mock 会把“Key 配错了”伪装成“模型回答得有点怪”，浪费排查时间。显式 `--mock` 表达“我知道现在是假数据”。mock 能验证 CLI 参数、流程、输出格式；不能验证网络、鉴权、真实响应结构——后者只能靠真实请求或 `httpx.MockTransport`。

### 4. 安全要求

- 代码里不出现任何真实 Key；示例一律写 `sk-xxx`。
- 不打印 `Authorization` header。
- 错误信息里只打印 URL、状态码、响应体摘要（截断到 300 字符以内）。
- 确认 `.gitignore` 已忽略 `.env`；`data/` 下的运行数据也不要提交。
- 如果你在调试时打印配置，Key 必须打码，例如 `sk-****abcd`。

## 提示

- 先用 `httpx.post()` 在交互式解释器里发一次请求，确认 URL、header、body 都对，再封装成函数。
- `base_url` 末尾可能带 `/`，一定要 `rstrip("/")` 后再拼 `/chat/completions`，否则会出现 `//chat/completions`。
- `response.json()` 在响应不是 JSON 时会抛 `json.JSONDecodeError`；先看状态码再看内容。
- 用 `with httpx.Client(timeout=...) as client:` 能确保连接池关闭；CLI 一次请求，开一个 Client 就够。
- `response.raise_for_status()` 抛的是 `httpx.HTTPStatusError`，它不会读响应体里的 `error.message`；建议拿到状态码后自己组织错误信息。
- 打印错误时不要打印 `request.headers`；`str(exc)` 一般只含 URL，安全，但自己拼消息时要注意。
- 如果 `finish_reason` 是 `length`，说明输出被 `max_tokens` 截断了，不是模型答错。
- 如果终端出现中文乱码或 `UnicodeEncodeError`，先试 `$env:PYTHONIOENCODING = "utf-8"`。
- 不要把 Key 写进 `config.py` 的默认值里，也不要写进 README 示例。
- 真实调用会花钱。调试时把 `max_tokens` 设小（比如 64），确认链路通了再放大。
