# M8：流式与界面

> 2026-11-18 完成。目标：把 M6/M7 的 HTTP 能力变成可用的界面，并让问答能逐字输出。

## 为什么这一层和前面不一样

M0–M7 全是"后端能力"：输入参数、返回 JSON，谁调用都一样。
M8 第一次出现**状态**——用户在看什么、问到第几轮、有没有待确认单。
Streamlit 的脚本每次交互都从头重跑，所以状态必须显式存放（`st.session_state`），
这不是框架的怪癖，而是所有前端（React/Vue）都有的同一个问题。

## 流式协议（SSE）

```text
请求：POST /ask/stream  {"question": "...", "top_k": 4, "mode": "hybrid"}
响应：text/event-stream

data: {"type":"meta","hits":[{"n":1,"doc_id":"发票与报销",...}]}
data: {"type":"delta","text":"红"}
data: {"type":"delta","text":"字"}
...
data: {"type":"done","citations":[{"n":1,"doc":"发票与报销","section":"4. 红字发票..."}]}
```

设计决定：
- **先发 meta**：用户立刻看到"查到了哪些片段"，而不是空白等待。
- **错误只能以事件形式发**：一旦发出 200 响应头，就不能再改状态码；模型失败用 `{"type":"error"}`。
- **配置错误要提前失败**：生成器是惰性的，路由里先调 `load_settings()`，否则会变成"200 后流中断"。
- **不缓存、不缓冲**：`Cache-Control: no-cache` + `X-Accel-Buffering: no`，否则代理会攒块。

## 界面结构

```text
sidebar    API 地址 / 健康状态 / top_k / mode
tab 1      知识问答：历史、流式打字机、引用、命中片段
tab 2      工单：过滤列表、详情+事件、新建、改状态
tab 3      Agent：对话、工具步骤、待确认卡片（同意 / 拒绝）
```

**前端只是 HTTP 客户端**：`streamlit_app.py` 不 import `app.rag` / `app.db` / `app.agent`。
这样以后换前端、加鉴权、拆服务，都不用改业务代码。

## 已知限制

1. **Agent 没有流式**：`/agent/chat` 要等模型多轮工具调用结束才返回。流式化的难点是"工具调用事件和文本增量混在一条流里"，留给以后。
2. **没有跨轮历史**：`session_id` 只绑定待确认单，用户说"那帮我退了吧"会丢失指代。
3. **单用户单机**：无鉴权、无限流；`session_id` 由客户端生成，可以伪造（但只能确认自己的单，因为服务端校验匹配）。
4. **会话状态全在浏览器**：刷新页面 history 丢失，但待确认单仍在数据库（`pending_actions`），需要的话可以做一个"我的待办"列表。
